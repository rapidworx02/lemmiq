LEMMIQ V2.8.3 - ADMIN CONTROL + RELIABILITY PATCH
==================================================

BASE REQUIRED
-------------
Apply this patch on top of your current working LEMMIQ V2.8.2 folder.

VERSION
-------
Backend / PWA: 2.8.3
Android versionName: 2.8.3
Android versionCode: 48

WHAT THIS PATCH FIXES / ADDS
----------------------------

1) Q VISION IMAGE MIME FIX + CLEAN RETRY
- Fixes PNG images being sent to the vision provider as image/jpeg.
- Backend now detects the real image format from file bytes (JPG/PNG/WEBP/GIF).
- Existing saved Vision media also repairs a wrong stored MIME when re-analysed.
- Raw provider/API errors are no longer shown to the user.
- User sees a simple retry message instead.
- Chat image action changes to "Retry Q Vision" after a Vision failure.

2) Q-TO-Q MULTI-CONTACT SEARCH / SELECTION
- Search and select one contact.
- Selected contact remains visible.
- Search again and add more contacts.
- Selected contact list shows name + @username.
- Remove individual contacts before sending.
- Send one Q-to-Q request to all selected users.
- Web and Android both updated.

3) FIXED 10-SLOT USDT WALLET MATRIX
Five subscription packages x two networks = 10 slots:

$10 Starter      TRC20 + BEP20
$50 Plus         TRC20 + BEP20
$100 Pro         TRC20 + BEP20
$500 Premium     TRC20 + BEP20
$1,000 Elite     TRC20 + BEP20

- Admin sees all 10 slots at once.
- One active receiving wallet per package + network.
- Replace / update wallet from the slot.
- Old wallet rows remain for historical payment records.
- New payment orders REQUIRE the exact package/network wallet.
- No generic fallback wallet is used.
- Historical QR URLs continue working after a wallet is replaced.
- Custom QR upload remains available.

IMPORTANT:
Only PUBLIC receiving addresses belong in LEMMIQ.
Never enter a seed phrase/private key/recovery phrase.

4) ADMIN Q LEDGER USER IDENTIFICATION
Admin ledger now shows:

User #10 · Display Name · @username

instead of only an internal user number.

User-to-user transfer example:
User #1 · Rohitz · @rohitz12345
→ User #27 · Shweta · @shweta21

5) MASTER ADMIN USER PACKAGE + WALLET CONTROL CENTRE
Admin can search users by:
- user number / ID;
- display name;
- @username;
- package;
- package status.

Each user shows:
- Q wallet balance;
- package(s);
- current daily return %;
- current maximum return %;
- earned Q;
- accrued USD reference value;
- how much return percentage has already been earned;
- package status;
- whether daily/cap settings are individual overrides.

6) MANUAL Q WALLET CORRECTIONS
Master Admin can enter a signed correction:

+100 Q  = add Q to the user's wallet
-50 Q   = remove Q from the user's wallet

Every correction requires an Admin reason and creates:
- a Q ledger entry; and
- an Admin audit entry.

Positive corrections move Q from PROMOTIONS treasury to the user.
Negative corrections return Q from the user to PROMOTIONS treasury.
This preserves the 1B Q supply instead of silently editing balances.

If PROMOTIONS does not have enough Q, transfer Q into PROMOTIONS from another
admin treasury wallet first.

7) INDIVIDUAL PACKAGE CONTROL
Master Admin can edit each package lot independently:
- daily return %;
- maximum return %;
- pause;
- resume;
- stop;
- cancel/remove from active use.

"Cancel / remove" is stored as ADMIN_CANCELLED instead of deleting the
financial record. Historical payment/package/audit data remains available.

8) EARNED PERCENTAGE TRACKING
Example for a $500 package:

Purchase value:          US$500
Accrued package value:   US$317.50
Earned percentage:       63.50%
Maximum return:          200%

Admin can see this for every package.

9) MASTER SUBSCRIPTION DAILY RETURN + MAX RETURN CONTROLS
Master Admin can edit the package defaults for:
- Starter
- Plus
- Pro
- Premium
- Elite

For each package:
- Daily return %
- Maximum return %

Primary action:
"Apply to all current + future"

This changes existing package lots as well as future package purchases.
Past earnings are NOT recalculated backwards.

Example:
Premium changes from 1.00% daily to 0.75% daily.
Existing Premium package accrual is brought current at the OLD rate first.
Future accrual uses 0.75%.

The Master Admin may optionally preserve individual user overrides. If that
option is NOT selected, the master change overrides custom user rates too.

A second option "Future packages only" is also available.

10) DIFFERENT MAXIMUM RETURNS PER USER
You can now configure, for example:
- User A max return = 200%
- User B max return = 150%
- User C max return = 100%

Individual settings remain marked as custom overrides until reset to master.

11) ADMIN AUDIT LOG
Sensitive changes are recorded with:
- admin user;
- action;
- target user;
- package lot (where relevant);
- previous settings;
- new settings;
- reason;
- date/time.

NEW DATABASE TABLES
-------------------
V2.8.3 adds new tables using SQLAlchemy Base.metadata.create_all():
- q_package_rules
- q_subscription_overrides
- q_admin_audit_logs

No manual SQL migration is required for these NEW tables.
Existing Q tables are not dropped or recreated.

IMPORTANT FINANCIAL RULE
------------------------
Cash-out remains DISABLED in V2.8.3.

Admin package edits are internal Q Economy controls. Before enabling cash
withdrawal/redemption later, complete the legal, financial, reserve, AML/KYC
and Australian regulatory work discussed for the Q Economy.
