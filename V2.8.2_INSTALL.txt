LEMMIQ V2.8.2 - REFERRALS + Q MARKET MEDIA + USDT UX
======================================================

WHAT THIS UPGRADE ADDS
----------------------
1. Tier-based referral rewards.
   - Free signup keeps the basic referrer reward and referred-user welcome Q.
   - If that referred user later buys a paid package, the ORIGINAL referrer
     receives an additional package-specific Q reward after Admin approves the
     USDT payment.
   - Every approved package order can generate one referral package reward.
   - Duplicate payment-order referral rewards are blocked.

2. User referral dashboard.
   Users can see:
   - referred users under them;
   - username/display name;
   - current active Q tier;
   - total Q earned from each referred user;
   - pending referral Q from a submitted package payment;
   - signup/package reward history;
   - total referred users, paid referred users and total Q earned.

3. Admin package referral reward controls.
   Initial configurable defaults in V2.8.2:
   - $10 Starter: 10 Q
   - $50 Plus: 25 Q
   - $100 Pro: 50 Q
   - $500 Premium: 200 Q
   - $1,000 Elite: 400 Q

   These are defaults only. Master Admin can change them from Q Admin.

4. Q Market media/files.
   Sellers can add up to 10 attachments to a product/service listing:
   - JPG/JPEG, PNG, WebP
   - MP4, WebM, MOV
   - PDF, TXT, CSV
   - DOCX, XLSX

   Limits:
   - images/files: 20 MB each
   - videos: 100 MB each

   Marketplace listing cards show media/attachment information. Sellers can
   add more media later, remove attachments and select a photo as the cover.

5. Improved USDT payment flow.
   - TRC20 and BEP20 are equal, full-width network choices.
   - Cancel is separate.
   - QR is substantially larger.
   - Tap QR to enlarge on Android/web.
   - Copy Address button.
   - Copy Amount button.
   - Copy Order ID button.
   - clearer selected-network warning.
   - Submit remains disabled until a transaction hash is entered.

6. Android version:
   versionName = 2.8.2
   versionCode = 47

7. PWA cache bumped to V2.8.2.

PACKAGE REFERRAL FLOW
---------------------
Example:
A refers B
-> B joins Free
-> A receives free signup referral Q
-> B receives welcome referral Q

Later:
B buys $500 Premium
-> B submits USDT payment
-> Admin verifies and approves
-> Premium subscription lot is activated
-> A automatically receives configured Premium referral Q

If B later purchases another approved package, that new approved package order
can generate its own configured referral reward for A.

PLAY PROTECT IMPORTANT
----------------------
There is NO legitimate "Play Protect bypass file".

A release APK signed with your existing LEMMIQ upload key is the correct type
of manual Android test build, but Android/Google Play Protect may still show
an unknown-source or app-scan warning because the APK was installed outside
Google Play.

Do NOT disable or bypass Play Protect for testers.

Once you create a Google Play Console developer account, use Internal Testing
with an AAB. Google Play distribution is the normal way to avoid sideloading
friction and preserve Play App Signing/update continuity.
